# 파일럿 활성화 체크리스트

**초기 상태: 미수락·비활성.** 체크박스를 대신 완료하지 않습니다. 각 항목에는 수행자·날짜·근거 링크를 남깁니다.

- [ ] 부총괄이 Pilot DRI 역할과 주간 운영 허용시간을 수락했다.
- [ ] 6~10명 참가자와 접수 범위·사용할 Route를 확정했다.
- [ ] 각 Route의 Primary·Backup이 해당 역할을 본인 댓글로 수락했다.
- [ ] 저장소·Project·Discord의 일반 참가자/DRI/부총괄 권한을 실제 계정으로 확인했다.
- [ ] 비참가 일반 계정의 접근 차단과 관리자 예외를 확인했다.
- [ ] Project 필드·4개 View·Auto-add·기본 Proposed 상태를 실제로 확인했다.
- [ ] 테스트용 `pilot:scenario`가 운영 기한·Assignee·Discord 알림을 만들지 않았다.
- [ ] 실제 Form 제출에서 생성되는 Markdown을 Fixture와 대조했다.
- [ ] 최초 SLA·휴무일·활성화일·10영업일 접수 마감·마지막 관찰 기한을 확인했다.
- [ ] 참가자에게 줄 제출 링크와 운영 안내를 확인했다.
- [ ] `PILOT_ACTIVE=false`로 멈추는 방법과 실행 중인 Workflow 취소 방법을 직접 확인했다.
- [ ] 활성화 승인 fingerprint를 확인하고 본인 댓글로 수락했다.
- [ ] 모든 준비가 끝난 뒤 `PILOT_ACTIVE=true`로 활성화했다. `AUTO_ROUTING_ENABLED=false`는 유지한다.

## 역할 수락·설정

담당자와 설정은 `config/pilot-settings.yml`에 반영합니다. 사전 합의 후 15분 검토를 시작하며, 준비되지 않았다면 보류해도 됩니다.
