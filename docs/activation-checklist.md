# 파일럿 활성화 체크리스트 양식

이 문서는 활성화와 종료 확인에 재사용하는 양식입니다. **이번 파일럿의 실제 완료 여부·수행자·확인일·근거와 판단은 [활성화 이슈 #1](https://github.com/UMC-PRODUCT/proposal-routing-lab/issues/1)에 기록합니다.** 이 파일의 체크박스는 완료 현황을 표시하지 않습니다.

진행 방법은 [운영 가이드](operator-guide.md#activate), 구축 당시 확인한 결과는 [검증 기록](verification.md)을 참고하세요. 이미 있는 검증 결과를 사용한다면 확인한 환경과 현재 설정이 같은지도 기록합니다. 담당자 수락과 활성화 승인은 반드시 본인의 댓글로 남깁니다.

## 시작 전 준비

- [ ] 부총괄이 Pilot DRI 역할과 주간 운영 허용시간을 수락했다.
- [ ] 6~10명 참가자와 접수 범위·사용할 Route를 확정했다.
- [ ] 각 Route의 Primary·Backup이 해당 역할을 본인 댓글로 수락했다.
- [ ] 저장소·Project·Discord의 일반 참가자/DRI/부총괄 권한을 실제 계정으로 확인했다.
- [ ] 비참가 일반 계정의 접근 차단과 관리자 예외를 확인했다.
- [ ] Project 필드·4개 View·Auto-add·기본 Proposed 상태를 실제로 확인했다.
- [ ] 테스트용 `pilot:scenario`가 운영 기한·Assignee·Discord 알림을 만들지 않았다.
- [ ] 실제 Form 제출에서 생성되는 Markdown을 Fixture와 대조했다.
- [ ] 최초 SLA·휴무일·활성화일·10영업일 접수 마감·마지막 관찰 기한을 확인했다.
- [ ] 참가자에게 줄 제출 링크와 운영 안내를 확인했다.
- [ ] `PILOT_ACTIVE=false`로 멈추는 방법과 실행 중인 Workflow 취소 방법을 직접 확인했다.
- [ ] 활성화 승인 fingerprint를 확인하고 본인 댓글로 수락했다.
- [ ] 모든 준비가 끝난 뒤 `PILOT_ACTIVE=true`로 활성화했다. `AUTO_ROUTING_ENABLED=false`는 유지한다.

## 항목별 확인 근거

완료한 항목마다 아래 정보를 이슈 본문이나 댓글에 남깁니다. 권한 화면·로그를 첨부할 때 자격증명은 포함하지 않습니다.

| 확인 항목 | 수행자 | 확인일 | 결과·근거 링크 |
|---|---|---|---|
| 작성할 항목 | GitHub 계정 | YYYY-MM-DD | 관찰한 결과와 링크 |

## 역할 수락·설정

담당자와 설정은 `config/pilot-settings.yml`에 반영합니다. 사전 합의 후 15분 검토를 시작하며, 준비되지 않았다면 보류할 수 있습니다. 역할 수락·승인 명령과 실제 접수 확인은 [운영 가이드](operator-guide.md#ready-check)를 따릅니다.

## 관찰 종료·인계

- [ ] 표본·기한 준수·운영 부담·다음 행동 이해를 함께 검토했다.
- [ ] 규칙 유지 또는 변경의 이유를 기록했다.
- [ ] 미결정·Parked 재검토·후속 업무에 인수자 수락과 목적지 링크가 있다.
- [ ] 승격 제안 / 수정 후 재실험 / 판단 유보 / 폐기 중 하나를 제안했다.
- [ ] 인계 완료 후 알림·Webhook·Project를 종료하고 저장소를 아카이브했다.

완료 여부는 [종료·인계 절차](operator-guide.md#close)의 확인 기준으로 판단합니다.
