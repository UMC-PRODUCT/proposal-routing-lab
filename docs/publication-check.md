토큰·개인키·AWS 키·Discord webhook/token·JWT·전화번호 패턴 검사에서는 일치 항목이 없었습니다. 기존 제어/연습 Issue는 합성 자료이며 실제 사용자 원본이나 배치 평가를 포함하지 않았습니다. 과거 안내의 Discord 채널 URL은 권한이 필요한 식별 링크이며 인증 토큰이나 대화 원문이 아닙니다. 새 공개 Registry에는 승인된 팀·PM 닉네임 배치와 미등록 계정 상태만 넣었으며 내부 배치 판단·실명·개인 사정 자료는 옮기지 않았습니다.

검사는 확인 시점의 파일·이력·Issue·로그를 대상으로 하며 미탐 가능성까지 없다는 보장은 아닙니다. 원본 감사 데이터와 로그는 커밋하지 않습니다. 공개 후 복제본·포크를 회수할 수 없다는 제약은 [운영 안내](operator-guide.md)에 명시했습니다.

## 원격 적용 (2026-09-13)

- 저장소 `visibility=public`, `private=false`를 API로 확인했습니다.
- main 보호 재조회: PR 승인 1인, CODEOWNERS 승인 요구, 변경 후 기존 승인 해제, 마지막 push 작성자 외 승인, 최신 기준 브랜치에 대한 `verify` CI(GitHub Actions App 15368) 필수, 대화 해결 요구를 적용했습니다. 관리자 우회·강제 push·브랜치 삭제는 허용하지 않습니다.
- CODEOWNERS의 실제 검토자는 미등록입니다. 설정 플래그만으로 모든 경로의 검토 책임이 작동한다고 판단하지 않으며 Registry의 `protection_verified=false`를 유지합니다. Registry 각 검토 영역에 최소 2명을 연결한 뒤 생성 파일·실제 권한·오류 응답을 다시 확인해야 합니다.
- `INTAKE_MODE=observe`, `PILOT_ACTIVE=false`, `AUTO_ROUTING_ENABLED=false`를 원격에서 확인했습니다. 새 접수 라벨 9개와 [운영 현황 #6](https://github.com/UMC-PRODUCT/proposal-routing-lab/issues/6)을 준비했습니다. 기존 #1~5는 보존합니다.
- `907c16e` 기준 [원격 CI](https://github.com/UMC-PRODUCT/proposal-routing-lab/actions/runs/34717922367)가 Python 3.12에서 전체 113개 테스트·Registry 검증·생성 파일 정합성을 통과했습니다.
- 새 자동화·양식은 검토 브랜치에서 구현했으며 main 병합 전입니다. 현재 공개된 main의 옛 안내를 v1 운영 개시로 해석하지 않습니다.

## 아직 필요한 검증

실제 구성원·PM·부총괄/대행 계정과 본인 수락, 실제 검토자 배정, 일반 구성원/Triage 제출·수락, CI 실패 PR 병합 차단의 실제 역할별 확인, 비개발 직군을 포함한 신규 구성원 3명의 사용성 확인, 운영 개시일은 준비 중입니다. 다른 사람의 인증·수락·승인을 대신 만들지 않았습니다. 이 항목과 PR 리뷰가 끝나기 전에는 운영을 시작하지 않습니다.
